当面对 3 个以上相近任务时，先按依赖关系和风险等级分批，再逐批推进。

分批原则：
- 按依赖关系排序：无依赖的任务优先，有依赖的任务等前置完成后再执行。
- 按风险分组：高风险改动单独成批，低风险改动可以合并。
- 每批明确输入、预期输出和验证方式。

输出格式：
1. 列出所有任务及其依赖关系。
2. 划分批次，说明每批的输入和预期产出。
3. 每批完成后验证结果，再推进下一批。

适用场景：
- 批量修改多个文件中的同类问题（如统一 API 调用方式、修复同类 lint 错误）。
- 多模块重构：先改接口层，再改实现层，最后改测试层。
- 批量生成或更新配置文件、文档、模板。

不适用场景：
- 单个任务或强耦合的连续编辑，直接执行即可，不要为拆分而拆分。
